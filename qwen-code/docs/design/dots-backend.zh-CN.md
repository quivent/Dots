# Dots 后端集成

[English](dots-backend.md) | [简体中文](dots-backend.zh-CN.md)

## 问题

Dots 需要使用完整的 Qwen 终端界面和现有的云端 Dot 后端。仅替换模型提供方仍会保留本地编程代理循环，可能发送内部提示或执行本地工具。

## 设计

显式的 `DOTS_BACKEND=1` 进程模式启动 Qwen 原有的 Ink 应用、`AppContainer` 和默认布局。Python JSON-lines 子进程负责 Dots 身份验证、已保存身份解析、消息、轮询和投递日志。Qwen 钩子使用此传输层替代 `useLlmStream`。

Dots 启动流程创建安全的 bare Qwen 配置用于界面展示。配置初始化跳过 LLM 初始化、钩子、MCP 发现、技能和文件检查点。凭据由 Dots 管理，因此跳过模型提供方身份验证。用户文本和支持的 Dots 命令会先于 Qwen 本地代理提交流程直接交给后端钩子。

退出时先等待 Python 工作进程完成当前操作并释放会话锁，再开始 Qwen 的限时清理。在清空输入框前拒绝附件；服务器上的消息编辑和删除会同步更新现有记录。

## 范围

复用 Qwen 的应用布局、文本缓冲区、输入组件、记录渲染、终端处理和主题。现有 Dots 后端继续负责单次发送和恢复。不添加模型提供方适配器，不执行本地工具，不自动恢复暂停的 Dot，也不自动重试投递结果不确定的消息。

## 文件

新增 Dots 启动模块、传输服务、后端钩子和 Python 桥接模块。为显式模式更新 Qwen 入口、应用容器和身份验证展示。

## 验证

使用离线测试数据验证历史加载、单次发送、输入时接收更新、暂停和不确定投递行为、斜杠命令路由及退出清理。运行针对性的 Python 和 TypeScript 测试、构建、类型检查和终端冒烟测试。真实提供方发送需要用户有意提交消息。

## 验收

Dots 命令启动 Qwen 现有 TUI，显示所选 Dot 的历史，并仅通过 Dots 路由提交的消息。不会运行 Qwen 提供方身份验证及本地模型和工具循环。Dots 模式之外仍可使用原有 Qwen 启动流程。
